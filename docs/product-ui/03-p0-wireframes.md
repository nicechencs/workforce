# Workforce P0 页面线框规范

**版本：** V0.1 Draft  
**状态：** Ready for visual design  
**日期：** 2026-09-13  
**修订：** 2026-09-13 — 壳上 Chat 按钮；§11 角色版本库；§12 全局 Chat 四类意图；去掉「无 Marketplace」永久句。均 planned。2026-09-11 — §7 只读 `GET /workflows` 目录为 M3 过渡（不是夹具冒充接通）；§10 画布、§11 自定义 Team、§12 对话生成与 §13 双执行模式为 M7/M8 planned 必达。2026-09-10 — 侧栏按 [IA §2](01-information-architecture.md) 含 P1「运行记录」「工作流」；§3 与 IA §4.3 对齐（概览不是 Overview；Task DAG 不在默认画布）。标题中的 P0 指主工作区切片，不隐藏 P1 一级导航。

## 1. 全局框架

桌面端采用左侧一级导航、顶部上下文区和主工作区。首屏不放营销内容。

侧栏成员以 [页面信息架构 §2](01-information-architecture.md) 为准：`P0`/`P1` 是切片深度，P1「运行记录」「工作流」必须画在左侧栏。§2–§6 与 §8 细化 P0 主工作区；§7 是 M3 工作流只读目录（`GET /workflows` 过渡）；§10 / §11 / §12 是 M7 画布、角色版本库 + Team 与全局 Chat；§13 是 M8 双执行模式。Chat 是顶栏壳按钮，不是侧栏「某员工」。

```text
┌──────────────┬─────────────────────────────────────────────┐
│ Workforce    │ 当前 Workspace / 页面     Chat  通知  新建 │
│              ├─────────────────────────────────────────────┤
│ 工作台       │                                             │
│ 项目         │                主工作区                     │
│ AI 团队      │                                             │
│ 执行节点     │                                             │
│ 审批中心     │                                             │
│ 运行记录     │                                             │
│ 工作流       │                                             │
│ 设置         │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

响应式规则：

- 宽屏：固定侧栏，主内容最多两列。
- 窄屏：侧栏折叠，关键操作保留在顶部。
- 移动宽度只保证监控和审批，不作为 V0.1 正式移动端。

## 3. 项目详情

标签文案与分区以 [01-information-architecture.md](01-information-architecture.md) §4.3 为准。下图是页头 + 默认 **概览** 画布，不是把 Task DAG 画进概览的许可。

```text
┌────────────────────────────────────────────────────────────┐
│ 项目名称                 执行中     开始执行 / 取消         │
│ 目标摘要 / Team / Workspace标签 / 预算（只读）              │
├────────────────────────────────────────────────────────────┤
│ 概览 | Tasks | Runs | Artifacts | Activity | Settings      │
├────────────────────────────────────┬───────────────────────┤
│ 目标、状态、Team、节点范围、进度计数 │ 只读摘要              │
│ （不是 Task DAG）                  │ Approvals: 1          │
└────────────────────────────────────┴───────────────────────┘
```

- WorkspaceBinding 写入、预算说明和策略说明在 **Settings**。
- Task DAG/列表、负责人、状态、依赖在 **Tasks**。
- 项目命令留在页头。

## 7. 工作流目录（M3 过渡，只读）

主工作区按 [IA §6.2](01-information-architecture.md) 的过渡切片：已发布模板、不可变版本、结构化步骤。数据来自只读 `GET /workflows`（及模板/版本详情），不是夹具。M7 画布见 §10。空目录诚实空态。目录接通不等于 Runtime 可执行这些定义。

```text
┌────────────────────────────────────────────────────────────┐
│ 工作流                                      在画布中编辑*   │
│ 只读目录 · 已发布模板 · 版本 · 结构化步骤（M3 过渡）        │
├────────────────────────────────────────────────────────────┤
│ Feature delivery           0.1.0 已发布 · 5 步 · 不可变    │
│ software-development-team.feature-delivery                 │
├────────────────────────────────────────────────────────────┤
│ 结构化步骤                                                 │
│ 1. 规划     任务 · planner · gate plan                     │
│ 2. 实现     任务 · developer · 并行                        │
│ 3. 整合     交付 · stable Node ID                          │
│ 4. 审查     任务 · reviewer                                │
│ 5. 验收     审批 · gate artifact                           │
└────────────────────────────────────────────────────────────┘
```

`*`「在画布中编辑」M3 禁用或隐藏；M7 进入 §10。

## 8. 新建项目流程

采用分步侧边面板或独立流程页：

1. 项目目标
2. WorkspaceBinding
3. AI Team
4. Task 计划与验收条件
5. 执行位置策略
6. 权限、预算和最终确认

V0.1 的执行位置默认值为“本机”；未来存在远程节点时可选择自动调度或指定节点。

## 9. 视觉基线

- 浅色界面，冷灰页面背景和白色内容卡片。
- 单一蓝色作为主要操作和选中状态，不使用蓝紫渐变。
- 绿色表示健康/完成，橙色表示等待/注意，红色表示失败/危险。
- 正文不小于 16px；常用标签不小于 14px。
- 边框、阴影和圆角克制，优先保证高密度信息的可读性。
- Node、Worker、Runtime 和 Run 使用不同文字标签与图标，不依赖颜色区分。

## 10. 工作流画布（M7）

按 [IA §6.2](01-information-architecture.md) 与 [D15](../planning/decision-register.md#d15-可视化工作流画布编辑器)。未发布图不得显示为可执行。

```text
┌────────────────────────────────────────────────────────────┐
│ 工作流 / Feature delivery          草稿     保存  发布      │
│ 未发布：Runtime 不会执行此图                                │
├──────────┬─────────────────────────────────────────────────┤
│ 节点     │                 画布                             │
│ 任务     │    [规划] → [实现 A]                             │
│ 审批     │              ↘                                   │
│ 条件     │               [整合] → [审查] → [验收]           │
│ 并行     │    [实现 B] ↗                                    │
└──────────┴─────────────────────────────────────────────────┘
```

- 已发布版本只读；再编辑创建新 version。
- 发布失败保留画布，不假装已发布。
- 不提供「在画布上直接 Run」作为 Task 完成。

## 11. AI 团队编排与角色版本库（M7）

按 [IA §4.6](01-information-architecture.md) 与 [D16](../planning/decision-register.md#d16-自定义-team-编排)。M3 只画只读预设卡；M7 才启用库与右侧编辑。成员目标是库中 `workerVersionId`，不是三字段身份。

```text
┌────────────────────────────────────────────────────────────┐
│ AI 团队 / 我的角色版本库                      ＋ 新建团队     │
├──────────────┬─────────────────────────────────────────────┤
│ 搜角色版本   │ 已发布 WorkerVersion                          │
│ reviewer-v3  │ 引用：Software Dev Team v2、自定义 Team A   │
│ （已发布）   │ [选用到当前 Team]  [fork 新草稿]  [归档]     │
│ 草稿         │                                             │
│ 更严 reviewer│ 未发布：不可被 Team 选用                     │
├──────────────┼─────────────────────────────────────────────┤
│ 预设         │ 自定义 Team 草稿                             │
│ Software Dev │ workerVersionId / 职责标签 / 数量          │
│ （只读）     │ wv_reviewer_v3 · reviewer ×1                  │
│              │ wv_developer_v2 · developer ×2              │
│              │                    保存草稿   发布版本       │
└──────────────┴─────────────────────────────────────────────┘
```

未发布草稿不能绑定后开始规划。未选 `workerVersionId` 不得点成成功。**现在不做商店一等面**；不要画可点成功的 Marketplace。未来经本库安装。

## 12. 全局 Chat（V0.1 就要有，planned）

按 [D17](../planning/decision-register.md#d17-对话式-agent-编排工作流) 与 [IA §6.4](01-information-architecture.md)。这是壳上随时可开的语言入口，不限于工作流作者页。创建流程仍可落到画布（§10）；创建角色确认后进 §11 库。authoring Agent 通过受治理 Runtime 执行，但不是生成物的执行窗口，回复气泡也不是完成。

```text
┌────────────────────────────────────────────────────────────┐
│ Chat                                         关闭            │
├──────────────────────────────┬─────────────────────────────┤
│ 用户                          │ 意图 / 对象预览              │
│ 建一个更严的 reviewer          │ 创建角色 → WorkerVersion 草稿 │
│ 做一条发布流程                │ 创建流程 → WorkflowDraft      │
│ 进行到哪了                    │ 问进度 → 还没有记录           │
│ 补一句：别动 schema            │ 交流工作 → 先问哪个项目      │
│                              │ 「去做」：unsupported         │
│ [说一句……]          发送     │ [去角色库] [打开画布编辑]     │
├──────────────────────────────┴─────────────────────────────┤
│ 确认后才落草稿。未发布不执行。完成只看 Artifact / Run / Approval │
└────────────────────────────────────────────────────────────┘
```

M3 不显示可点击成功的生成入口。HTTP 未就绪时壳说明未接通。创建类须用户确认；问进度只渲染投影事实；没有 `projectId`/`runId` 不发写。生成出的 Workflow 不得在发布/计划确认前执行，也不得写入 Secret。不得把 bot 回复画成已完成或已在跑。

## 13. Agent 执行模式（M8 planned）

按 [D18](../planning/decision-register.md#d18-双执行模式绑定工作流与直接执行)。模式选择只在 capability probe 支持时启用，两个选项最终都创建受治理 Task/Run。

```text
┌────────────────────────────────────────────────────────────┐
│ 启动 Agent Task                         能力：已探测         │
├────────────────────────────────────────────────────────────┤
│ 执行模式                                                     │
│ ○ 跟随已发布工作流  WorkflowVersion: v3                      │
│   只执行图中轮到该 Agent 的节点                              │
│ ○ 直接执行（ad-hoc）                                          │
│   当前目标；仍受 Policy / Workspace / Budget / Approval       │
│                                                            │
│ transport: process    placement: Local Node                  │
│ [开始]  [取消]                                                │
├────────────────────────────────────────────────────────────┤
│ 无能力时：模式 disabled，显示 unsupported_capability 原因      │
└────────────────────────────────────────────────────────────┘
```

`workflow_bound` 需要已确认 Project Execution Snapshot，并从中读取 WorkflowVersion/TeamVersion；`direct` 只绕过本次图调度，仍创建项目内 ad-hoc Task/Run，永不推进 WorkflowInstance/Project。若吸收成果，必须另发 workflow-bound/follow-up command，引用精确 ArtifactVersion 并重新验收。M3 隐藏该选择面；未冻结字段前不得实现假按钮。
